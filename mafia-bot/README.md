# 🔥 Выживает сильнейший — Telegram-бот

Готовый исходный проект на русском языке. Python 3.11+, без сторонних Python-пакетов. Бот пока не зарегистрирован и не запущен: для этого нужны ваш токен от BotFather и компьютер или сервер с постоянным интернетом.

## Быстрый запуск с Docker

1. Откройте https://t.me/BotFather, отправьте `/newbot`, задайте название и username. Скопируйте токен. Не публикуйте его и не отправляйте другим людям.
2. Распакуйте архив, откройте терминал в папке `mafia-bot`.
3. Скопируйте `.env.example` в `.env`, замените `PASTE_TOKEN_FROM_BOTFATHER` своим токеном.
4. Установите Docker с Compose и выполните:

```sh
docker compose up -d --build
docker compose logs -f
```

Остановка: `docker compose down`. Сохранение состояния находится в томе `mafia-data`; не удаляйте его, если хотите сохранить игру. Один токен — один запущенный экземпляр бота.

## Без Docker

Установите Python 3.11 или новее. В Linux/macOS:

```sh
export BOT_TOKEN='ВАШ_ТОКЕН'
python3 bot.py
```

В PowerShell Windows:

```powershell
$env:BOT_TOKEN='ВАШ_ТОКЕН'
python bot.py
```

Файл `.env` автоматически читает только Docker Compose; при запуске Python задавайте переменные окружения. Компьютер должен оставаться включённым. `NIGHT_SECONDS`, `DISCUSS_SECONDS`, `VOTE_SECONDS` задают длительности (минимум 15 секунд). Состояние сохраняется в `data/state.json`, путь меняется через `STATE_PATH`. Защищайте файл: он содержит роли и Telegram ID.

## Как сыграть

1. Добавьте бота в обычную группу или супергруппу. Бот не удаляет сообщения и не требует назначения администратором; privacy mode можно оставить включённым. При нескольких ботах используйте `/команда@username_бота`.
2. Каждый игрок открывает личный чат с ботом и нажимает `/start`.
3. В группе: `/newgame`, затем каждый участник отправляет `/join`.
4. Создатель игры или администратор запускает `/begin`. Нужно от 4 до 20 человек.
5. Роли приходят лично. Ночные действия — кнопками в личном чате, дневные голоса — кнопками в группе.

Команды: `/help`, `/newgame`, `/join`, `/leave` (до начала), `/begin`, `/players`, `/stop`, `/roles`, `/myrole`.

## Правила «Выживает сильнейший»

Каждый играет за себя, побеждает последний живой. В игре от 4 до 20 человек. Роли выбираются случайно без повторов из полного списка 20. При 20 игроках участвуют все роли; при меньшем составе — случайный набор. Стартовое здоровье — 100 HP. Команд нет.

Команда `/roles` показывает все роли. `/myrole` в личке показывает свою роль, HP, усиление и остаток применений. В группе секреты не раскрываются.

### Ходы и порядок расчёта

Ночью каждый выбирает ровно одно действие: обычную атаку (25 + усиление), защиту или припасы (+15 HP и +5 усиления). Максимум здоровья — 100, усиления — 20. Ролевые бонусы к атаке прибавляются сверх усиления. Специальные ночные способности заменяют обычный ход. Последняя кнопка заменяет предыдущий выбор; применение тратится только при расчёте ночи. Без выбора включается защита.

Порядок: регенерация мутанта в начале ночи → выбор действий → припасы/эликсиры/кражи → одновременные атаки → ловушки, яд и арена → месть → проверка победителя. Атаки используют усиление на начало ночи; украденное и найденное усиление действует со следующей ночи. У охотника бонус появляется после завершения фазы, в которой погибла цель.

Защита сокращает суммарный обычный урон от атак вдвое с округлением вверх. Броня и укрытие снижают обычный урон, но не выстрел. Призрак избегает и обычных атак, и выстрела. Яд, ловушки, месть, совет и арена игнорируют защиту. Скрытие не блокирует яд или кражу. Лечение не воскрешает.

Вампир получает треть своей доли урона по цели (в пределах её HP после лечения, до урона арены/яда). При нескольких нападающих доля распределяется пропорционально исходной силе атак, округление — по Telegram ID. Лечение вампира применяется перед входящим уроном, максимум 100 HP. Месть срабатывает только если сами атаки были смертельными; смерть от яда/арены/ловушки месть не вызывает. Ответная месть не образует цепочку.

Днём — обсуждение, затем голосование. Лидер теряет 35 HP (кроме первого наказания Неприкосновенного). Самоголосование запрещено. Ничья или лидер «воздержаться» означают отсутствие наказания. Пропущенные голоса не учитываются. Усиление Агитатора действует только на один ближайший совет и тратится при активации, даже при воздержании.

С третьей ночи арена наносит всем 10 урона, с четвёртой — 20 и так далее до 100. Этот урон нельзя блокировать. Если одновременно погибли все, победителя нет. Здоровье публичное, роли раскрываются после конца; разведчик узнаёт их раньше. Бот поддерживает несколько групп, но игрок участвует только в одной игре. Выбывшие и посторонние не могут ходить; старые кнопки недействительны.

### Обновление и размещение

Остановите старый экземпляр, замените исходники и пересоберите контейнер: `docker compose up -d --build`. Не удаляйте том `mafia-data`. Уже начатые партии сохраняют старые роли; прежний «Выживший» преобразуется в Броненосца. Полная новая раздача будет в следующей игре.

Для Railway используйте этот Dockerfile, переменную `BOT_TOKEN` и постоянный том, смонтированный в `/app/data` (права записи пользователя контейнера обязательны). Домен и входящий HTTP-порт боту не нужны: используется long polling. Запускайте один экземпляр, отключите усыпление процесса. При необходимости задайте `STATE_PATH` на записываемый путь постоянного диска.

## Проверка и ограничения

```sh
python3 -m unittest discover -s tests -v
```

Проверки работают без токена и подключения к Telegram. Реальный запуск требует вашего токена и не проверялся в вашем аккаунте. Это базовая игровая версия без магазина, рейтинга, платежей, общения мафии через бота и автоматического запрета сообщений выбывшим.

Состояние и таймеры сохраняются после перезапуска. Если бот был выключен дольше таймера, просроченная фаза завершается при запуске. Запись на диск атомарная, но доставка сообщений в Telegram и запись состояния не образуют единую транзакцию: при аварии возможны повтор сообщения или пропуск уведомления. Следите за журналом; при сбое раздачи игра отменяется. Сетевые ошибки не раскрывают токен в логах. Для большой публичной нагрузки нужны отдельная БД, очередь доставки и мониторинг.
